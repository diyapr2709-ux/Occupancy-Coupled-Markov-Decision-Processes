# Decisions, 2026-11-24

One line per non-trivial choice: what was chosen and what decided it.

- **The half-finished temperature rewrite in the committed tree is finished, not reverted.** At `f113f44` the agent code already had the scalar temperature of `arena/2026-11-23-temperature-outcome.md`, but `experiments/train_agent.py` and five test files still called the removed per-state temperature head: 15 tests failed and the training script could not run. Now the training script reads `agent.temperature()`, records each agent's reachable entropy range and target per run, and `--set` accepts `temperature=fixed` or `temperature=auto`. New tests cover the reflecting loss at both clamp edges, the reachable range with tied drugs, a fixed temperature that never moves and a learned one that stays inside its clamp. One test bound was wrong and is corrected: with classes of 3 and 1 tied drugs the entropy spent inside classes is q_big log 3, so its bound is log 3, not 0.75 log 3, which only held while the old near-uniform policy kept q_big at or below 0.75. Decided by: the arena outcome sets the protocol the next runs follow, and reverting would have left them on the one it replaced. The broken state stays in history at `f113f44`.
- **Runs before and after this change are not seed-comparable.** Removing the temperature head changes the random draws at network initialisation, so the same training seed starts from different weights, and the temperature objective itself changed. Reports up to `runs/train/train_20261123_194806_29133.json` are diagnostics of the previous design.
- **Every trained agent is saved as a checkpoint, on every backend, and kept in the repository.** Each job returns its agent's weights together with the configuration and shapes that rebuild it (`checkpoint_bytes` and `load_checkpoint` in `ocmdp/agents/oc_sac.py`, read with `weights_only`). The driver writes them to `runs/train/checkpoints/<report name>/<variant>_sigma<s>_seed<k>_q<decisions>.pt`, and the report records each file's path, SHA-256, size and training decisions. `--checkpoint-every Q` adds intermediate checkpoints for checkpoint choice on val. Saving draws no random numbers, so training is identical with or without it (tested). A test reloads every checkpoint a run writes and reproduces that run's per-episode argmax evaluation exactly. `.gitignore` still ignores `*.pt` except under `runs/train/checkpoints/`. Decided by: the owner's instruction to keep the Modal checkpoints in the repository. Writing them from the driver rather than to a Modal volume gives one location whichever account or machine trains, and ties every file to its report by hash.
- **Checkpoint size:** one checkpoint is 993,394 bytes at the default sizes on PairedDrugs (242,840 stored values across the seven networks; measured with `checkpoint_bytes`, not a run), so a default dev report of 20 agents adds about 20 MB to the repository. Git LFS would hold this better; installing it is the owner's decision.
- **No checkpoints exist for the runs logged so far.** No job saved weights. The Modal account that ran them has no app running and no volume from this project (checked with the Modal CLI). Those agents can only be retrained.
- **Ledger line `2026-11-24T12:22:58|val|` is a file patch, not a launch.** The tier guard matched the usage text `--tier val` quoted in the patch to `experiments/train_agent.py`, which the same command modified at 12:23:06. No run was launched today and no report belongs to that line.
- **From today, training runs are launched on a second Modal account or a local GPU host, not from this machine.** Both agents of a pair always run on one backend, and results from different platforms are compared statistically, never seed by seed.
- **Every report now says where and how it ran, and every launch leaves a record (report schema 2).**
  - Each training job records:
    - the CPU features numpy detects for itself (the CPU model is hidden in Modal containers);
    - torch's thread count and CUDA visibility;
    - a hash of the machine's name, never the name;
    - the process id and the job's order within its process or reused container;
    - Modal's task and region variables when present;
    - SHA-256 hashes of the agent's weights at initialisation, after the first update window and at the end. The final hash equals the reloaded checkpoint's, and the initial hash is identical for both agents of a seed (both tested).
  - Each report carries a schema version, a launch id and a `--platform` label, which is required for val and test. It also records the preregistration's SHA-256.
  - Each launch writes `launches/<launch id>.json` next to its reports before any job starts.
  - Training jobs are submitted interleaved by seed.
  - Decided by: the standards reviewer's round 3, and the owner's go-ahead. Launches by hand on another account bypass the Claude Code hook, so neither the ledger nor the budget sees them. Two Modal accounts produced identical backend blocks, and the diverging containers of `train_20261123_190717_20498` and `train_20261123_194806_29133` could not be told apart.
- **Test-tier conditions are enforced inside `experiments/train_agent.py` and `experiments/sweep_phase_diagram.py`, not only by the hook.**

  - A launch on the val tier from uncommitted code is warned, not refused. That is weaker than the reviewer's rule: refusing would also refuse the test suite's own val-tier CLI tests, which run on the working tree. The owner may tighten it.

- **Fixed in a second batch from the validator's passes 4 and 5:**
  - **Phase-prediction scorer.** Measured and predicted crossings are both clamped to the range the grid can resolve. Before, a prediction below the first positive noise level, or a measured crossing between 0 and that level, was penalised against a "below the grid" answer that meant the same. The crossing is now where the contrast settles into its stated sign, not its first sign change. A line with no nonzero mean counts as not crossed. Reports evaluated on different episodes are refused. One test expectation changed with the censoring: a prediction of 0.05 against a measured 0.2 now scores log 2, not log 4, and still fails the margin.
  - **`t_quantile`.** It widens its bracket instead of stopping at 1000, so df 1 at 0.9999 gives about 3183. It refuses probabilities outside (1/2, 1) instead of returning about 0.
  - **`load_checkpoint`.** It rebuilds the agent on a forked random state, so loading no longer moves torch's global generator.
  - **Test-tier preregistrations.** A preregistration must be a file in `preregistrations/`. Its SHA-256 is read at launch and recorded in the launch record.
  - **Gap attribution.** The docstring now states that the split depends on the order of its links, that the first link also counts the objective mismatch, and that the last includes ordinary sampling. Choice losses below 1e-12 are treated as ties.
  - **Bootstrap.** The docstring of the crossed bootstrap states its under-coverage where seed variance dominates, and that the t interval stays primary.
  - **Inbox.** The three source mischaracterisations are corrected in place, each marked as a correction.
